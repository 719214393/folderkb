    ② 嵌入模型（RAG 检索用，不开 RAG 可不填）
    RAG 知识库检索需要嵌入模型（bge-m3，免费）。只在开启 RAG 提问时使用；换服务商时把模型名改成对方的名字。
    ③ 重排模型（可选——不单独配就沿用上面的嵌入配置）
    跨编码器重排（bge-reranker-v2-m3，免费）把召回池按相关性精排，是命中率关键一环。用别家（Cohere / Jina 等）把地址、Key、模型名一起改掉即可。
    ④ 检索档位（重排候选池深度——影响召回与成本）
    池越深召回越全但重排 API 调用越多（成本≈池深比例）。评测口径是均衡档（100）——改档位后评测数字不直接可比。
    成本预估：快 ≈0.6× ｜ 均衡 ≈1×（基准）｜ 深 ≈1.5× —— 单次检索约 0.5-3 秒，深档多约 1 秒
    ⑤ 检索模式（RAG 问答方式）
    Agentic 档多跳题更准（模型自己拆问补查）；流水线档更快更省 token（单次检索）。
    ⑥ 对话引擎（双链对照期）
    两链应答一致；发现差异报 trace_id 给开发者。D-6.0b 对照期通过后旧引擎将移除。
